# 阶段 4：Word 五件打包

把 md 草案变成五个符合 CNIPA 格式的 docx。**本文件只说怎么做出来，稿件应该长什么样见 `02-撰写规范.md` 第 11 节，格式数值只在那里出现一次。**

## 五个标准件

| 文件名 | 内容 |
|---|---|
| `100001权利要求书.docx` | 权利要求书 |
| `100002说明书.docx` | 说明书正文（五段式） |
| `100003说明书附图.docx` | 全部附图，带图号图题 |
| `100004说明书摘要.docx` | 摘要 |
| `摘要附图.docx` | 摘要附图，不带图号标注 |

编号前缀是 CNIPA 的标准件号，不要改。

## 管线

```
md 草案
  → build_docx.py   以官方空白模板为底稿写入；LaTeX → MathML → OMML
  → verify_docx.py  程序化格式体检
  → 独立终审        另写检查，不复用自检脚本
  → 用户真开 Word   目视验收
```

```bash
python scripts/build_docx.py  --project <专利>/v<N>
python scripts/verify_docx.py --project <专利>/v<N>
```

两个脚本都从 `<专利>/v<N>/patent.json` 读发明名称与附图清单，脚本里不含任何具体专利的内容。
配置字段与 md 骨架约定见 `scripts/README.md` 与 `scripts/template.md`。

**最后一步不能省。结构校验通过不等于 Word 能正常打开和显示。** 实际发生过：脚本全过、python-docx 不报错，Word 直接拒绝打开文件。

## 模板用法（关键）

**不要从零建文档。** 用官方空白模板 docx 打开后删掉正文、保留其余一切。

- 模板是**双节结构**：正文节 + 文末的「注意事项」节。正文写进第一节，**注意事项节整体保留在文末**，不要删（正式申请件就是这样）。
- **页眉页脚部件必须原样保留，只替换其中的文本。** 自己重建会丢掉 VML 画的横线、加粗设置和字距（实测丢过 130 缇的字距）。
- 页码用 PAGE 域，但**不要带 `w:dirty` 标志**，并预先写入结果文本，否则用户打开时会弹「是否更新域」。
- 如果某个标准件的官方模板是旧版 `.doc`（python-docx 打不开），可以借用同套的 `.docx` 版式，但**要把文末注意事项的文本替换成该件自己的那几条**，并把页眉件号改对。这属于权宜之计，最终以代理机构意见为准。

## 公式转 OMML 的三个必坑

这三个 python-docx **全都不报错**，要到 Word 里才发作：

1. **`m:oMathPara` 必须包在 `w:p` 里。** 直接挂到 `w:body` 下，Word 严格校验会拒绝打开整个文件。
2. **求和的被加项必须放进 `m:nary/m:e` 槽。** MathML 里 Σ 的上下限和被加项是兄弟节点，OMML 要求被加项进 `m:e`；漏放的话 Word 显示成虚线空框。嵌套求和要递归消费兄弟序列。
3. **`m:naryPr` 里不要写 `m:grow`**，否则 Σ 会随内容放大到整行高。括号 `m:dPr` 里的 grow 是正常的，要保留。

## 改公式里的字符

Word 重新保存会把公式里的 U+2212（−）归一化成 ASCII 连字符、ℝ 归一化成 R。还原时：

- **只能遍历 `<m:t>` 元素改其文本**，严禁对 `document.xml` 做全局字符串替换——`w14:paraId`、样式名里也有连字符，会被打坏；
- 按取值集合建白名单排除，比如 `LD-SW=`、`RMSE=`、`ReLU`、`ResBlock` 这类本来就带连字符或带 R 的；实数集只改「恰好等于 R」的元素；
- 验收用「符号计数与改动前基线逐项相等」。

## 验收

### 程序化体检

`verify_docx.py` 跑的检查项（第一篇是 12 项）：

存在性、发明名称居中、编号完整性、OMML 计数与源文一一对应、表格逐格抽查、图片计数、内部注记零泄漏、**`w:body` 直接子元素白名单**、双节与页眉页脚、字体字号缩进行距、**公式参数槽非空**、PAGE 域 dirty 与 Σ 的 grow。

后两项加粗的是被真实故障倒逼加进去的，不要删。

### 独立终审

Agent 的终审**必须另写检查，不复用自检脚本**。脚本和脚本作者共享同一套盲区，自己检自己必然漏。终审要覆盖：关键短语齐全、五段式完整、术语无旧词泄漏、摘要字数、公式结构、附图张数与图号、页边距与模板一致、受保护文件零改动。

### 用户目视

必须用户真开 Word 看。不同 Word 版本的渲染差异，结构校验覆盖不到。

## 常见返工点

第一篇打包经历六轮修复才收敛，触发的原因依次是：

1. Word 拒开（`m:oMathPara` 直挂 body）；
2. 排版不符（字体字号被误设、页眉残留、页脚缺页码）；
3. 公式显示空框（`m:nary/m:e` 槽没填）；
4. 页眉横线消失、注意事项位置错、缺首行缩进、打开弹域更新框、Σ 过大；
5. 编号标点、名称字体、节标题样式、缩进方式与实样不符；
6. 行距（实样是固定值 24 磅，此前误判成单倍行距）。

**规律**：前三轮是程序错误，后三轮全是「与实样对不齐」。所以打包前先把格式基准逐项落实（`02` 第 11 节），比事后一轮轮试错快得多。

## 写任务书给别人做时

如果把打包交给另一个 agent 或工具执行：

- **把「现状描述」和「目标状态」都写进任务书**，只写「执行某动作」的话，对方发现不了前提错误。实际发生过：任务书写错了一个需求，执行方核对现状后拒绝执行并说明理由，判断是对的。
- **产物落盘位置要写死**，否则报告、备份、脚本会散落到项目根目录污染工作区。
