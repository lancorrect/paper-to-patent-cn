# 阶段 2b：去 AI 味

> 方法改写自 academic-humanizer（MIT 许可，声明见 `licenses/academic-humanizer-MIT.txt`）。原 skill 面向英文论文和基金申请，这里按中文专利重写了词表、分区和保护清单，基金申请部分未采用。

**目标：在第一遍成稿时去除 AI 味，只动表达，不动技术内容。**

不以任何检测分为目标，不设检测器环节，也不用于规避 AI 使用的披露义务。机构或学校要求披露时照常披露。

## 何时跑

`02-撰写规范.md` 第 13 节自查全过之后、阶段 3 附图之前，**只跑这一次**。

- md 这时还是事实源，阶段 5 之后再整篇改写，代价和风险都大得多；
- 附图文字取自 S1–Sn，放到附图之后，改一处步骤措辞就要重核图；
- 后续 vN 和 `revise_vN` 不跑整篇改写。返修要求全程修订模式留痕，整篇改写也做不到。

**执行者必须是没写过这份稿子的模型，默认 Codex。** 它读稿时不带撰写时的判断，所以审计本身同时起到盲审的作用，不再单设盲审。派发方式按本机环境选。任务书写成文件让它自己读，不整段粘进 prompt。

校验命令：

```bash
python scripts/check_style_invariants.py 草案.改前.md 草案.md --terms 术语表.txt
```

用户决定修改权利要求后加 `--allow-claims`；术语确需增减时加 `--allow-term 某词`。退出码非 0 就不能往下走。

### 第 4 步要查什么

脚本只能证明数字、公式、术语、固定句式没变，下面这些只能靠人工核对：

1. **有没有新增技术断言。** 原文没有的机理、因果、效果、比较，一律退回。这是改写最容易犯的错。实测：拿一次真实改写跑校验，抓到它新增了原文没有的「97–120h 时段差距最明显」及一句因果解释；人工对照又发现「单步回归的值域也随之收窄」「与远处气象格点的关联较弱」这类原文没有的说法。
2. **保护范围有没有变。** 「可以采用」改成「采用」会收窄；「基本不增加参数」改成「不引入可训练参数」改变了技术表述。
3. **有没有改写带来的新痕迹。** 对称的收束句、整段长度相同的短句、过于口语的说法（如「本可以……却没有用上」），以及把连贯的句子拆碎（见「连贯优先」）。
4. **与权利要求的对应是否还成立。** 说明书的表述要继续支持每一条权利要求。
5. **结论句与表格是否一致。** 比较结论要能从表格算出来。实测：上面那句「97–120h 时段差距最明显」按表格计算并不成立，六种污染物的最大差距都不在这个时段。

## 分区规则

很多格式化表达正是专利要求的，不能当成 AI 痕迹处理。

| 区域 | 级别 | 允许的操作 |
|---|---|---|
| 权利要求书全部 | **只报不改** | 命中项写进审计表，由用户决定。权利要求界定保护范围，改动视为内容变更，回到映射审核门 |
| 公式、符号说明段 | 冻结 | 不动 |
| 公式引出句（「具体……的计算过程如下：」） | 冻结 | `02` 规定的固定句式 |
| 数据流向句（「本步骤获得的 X 提供给步骤 SY。」） | 冻结 | `02` 规定的固定句式 |
| 文末兜底声明 | 冻结 | 不动 |
| 表格及其数字 | 冻结 | 红线 1 |
| 技术领域 | 冻结 | 不动 |
| 实验条件（数据集、参数、指标定义） | 冻结 | 不动 |
| 发明内容里的 S1–Sn | 只报不改 | 与权利要求一一对应，连续操作用逗号连成一句，不拆句、不换词、不分段 |
| 实施例各步的操作句 | 只报不改 | 同上 |
| 附图说明 | 只删冗余 | 图号与图题对应不变 |
| 摘要 | 可改 | 保持结构，不超过 300 字 |
| 发明内容的引言、要解决的技术问题 | 可改 | 与权利要求的对应不变 |
| 实验结论与结果讨论 | 可改 | 比较结论和原因归因只报 |
| 背景技术 | **重点** | 可改 |
| 有益效果 | **重点** | 可改，并遵守下面的「主张与证据」 |
| 实施例的设计理由句、机理说明句 | **重点** | 可改。同一句既写操作又写理由时，默认只报 |

`>` 批注和模板说明不审。分不清属于哪个区域时，按较严的一档处理。

## 连贯优先

**拆句不是目标。** 专利正文的连贯靠逗号和连接词，同一层意思写在一句里。把逗号改成句号只在下面两种情况下做，每句最多断一次：

- 一句话里转入了另一层意思。例如前半句讲预算少的利弊，后半句转到这种利弊因样本而异；
- 长因果链的结论之前。前面的原因保留逗号，结论用「因此」「所以」引出。

连续的操作、同一层意思的连续陈述、设计理由的前因后果都不拆。句子长本身不算问题。

实测：第二篇首跑把 8 处逗号改成句号，用户只留下 1 处（转入另一层意思的），退回 6 处，另有 1 处去掉了句号。退回的是 S1–Sn 的连续操作和有益效果、设计理由的连续陈述，用户认为这样稿子更碎了。另有 2 处只报的长因果链，用户接受在结论之前断开。

## 中文痕迹清单

只收写作套语，不收领域词。命中不等于必须改：结合上下文判断，判断不准就只报不改。

审计表要写清问题在哪，不能只因出现关键词就报。「显著性」这类术语、「基本不增加参数」这类有意义的近似、「所有国控站点」这类范围限定都不算痕迹。

| 类型 | 常见写法 | 改法 |
|---|---|---|
| 套路开头 | 近年来、随着……的快速发展、在当今……时代、受到广泛关注、已成为研究热点 | 直接写现有技术怎么做、局限是什么 |
| 意义拔高 | 具有重要意义、至关重要、发挥关键作用、奠定基础、开辟新途径、赋能、助力、彰显、颠覆性、革命性、突破性 | 删掉，或改成具体做了什么 |
| 过度断言 | 显著提升、大幅提高、极大地、彻底解决、完全避免、确保、保证、必然、所有 | 有实测写实测，没有就用平实的定性说法 |
| 空泛强调 | 广泛、大量、丰富的、诸多、各种、多种多样 | 写具体对象，写不出就删 |
| 新颖性堆砌 | 首次、新颖的、独特的、巧妙地、创新性地、创造性地 | 删 |
| 模糊限定 | 较为、相对而言、一定程度上、某种意义上、基本上 | 能量化就量化，不能就删；不得为此新增数字 |
| 套话强调 | 值得注意的是、需要指出的是、值得一提的是、众所周知、显而易见 | 删掉引导语，直接陈述 |
| 空洞收束 | 综上所述、上述缺陷导致……制约了……、为……提供了有力支撑、具有广阔的应用前景 | 没有新信息的收束句整句删 |
| 长因果链 | 通过……，从而……，进而……，并使…… | 在结论之前断开一次，用「因此」「所以」引出结论，不要每层都断 |
| 排比对称 | 不仅……而且……、既……又……、一方面……另一方面、不是……而是……；凑够三项的并列（高效、准确、鲁棒） | 改成直述，并列只留实际存在的项 |
| 连接词连用 | 连续两句以上句首用此外、另外、同时、其次、而且 | 靠逻辑衔接，去掉连接词 |
| 翻译腔 | 被……所……、「基于……的……的……」连续堆定语、通过……来实现……、使得……得以……、对……进行……（高密度时） | 按中文习惯重写 |
| 优势堆叠 | 具有 A、B、C 等优势，已成为主流 | 说清楚具体差别 |
| 破折号 | —— | 全部去除，改用逗号、冒号或分句 |
| 第一人称 | 我们、笔者 | 改成「本发明」「本实施例」 |
| 长句 | 一句话里转入了另一层意思却没有句界。只是字数多、分句多不算命中，必要的技术列举也不算 | 在转折处断开一次，其余保留逗号，拆不自然就只报。权利要求不拆 |
| 碎句 | 同一层意思被句号切成一串短句，前后没有衔接 | 并成一句，用逗号和「而」「由于」「因此」等衔接。连接词只能表达原文已有的关系，不得新增因果 |

### 示例

改前取自真实稿件，改后按本规则重写。

**价值收束**

- 改前：因此，开发高精度、动态化的空气污染物预测方法，对发布健康预警、优化污染防控政策具有重要意义。
- 改后：高精度的污染物预测可用于发布健康预警和优化污染防控政策。

**长因果链**

- 改前：……筛选出显著相关的气象格点，仅在所筛选区域内进行交叉注意力耦合，从而在基本不增加参数的前提下降低交叉注意力的计算量与显存占用，并使各城市聚焦于与其相关的气象信息。
- 改后：……筛选出显著相关的气象格点，仅在所筛选区域内进行交叉注意力耦合。这样基本不增加参数，交叉注意力的计算量与显存占用随之下降，各城市也只读取与其相关的气象信息。

**空洞收束**

- 改前：上述缺陷导致预测模型难以准确刻画多污染物协同演变规律，制约了预测精度与实用性。
- 改后：整句删除。前文已列出三方面局限，这句没有新信息。

## 保护清单（不要误改）

- **术语不换同义词。** 同一概念反复用同一个词是专利要求，「所述」的重复也是。
- **专利惯用语不算痕迹**：进一步地、具体地、其中、本实施例、本发明（用在发明内容）。
- **说明书里的「可以」「可」「例如」要保留。** 这是给保护范围留余地，不是含糊。不得改成确定语气。权利要求禁用「例如」的规则见 `02` 第 9 节。
- **权利要求里 S1–Sn 之间的分号保留。**
- **无主语句和被动句可以保留**，施动者不重要时这样写是对的。
- **不增、删、改任何数字、公式、技术特征和效果。** 去掉没有依据的程度副词（显著、大幅）属于表达调整，可以改；效果的有无、对象和比较结论不能改，拿不准就只报。
- **作者手写的句子可能也被命中。** 判断不准时只报不改，由用户决定。

## 主张与证据（只用于有益效果）

每条效果都按「特征 → 机理 → 效果」写，并核对：

- 实测效果：数字要有来源，写明比较对象和条件；
- 理论预期：可以不带数字，但不能写得像实测；
- 动词不强于证据：没有数字支撑就不写「显著提高」；
- **没有数据时不为了满足这条规则去补数字。** 红线 1 优先。

## 语体样本

`config.local.md` 里列出作者手写稿和代理机构定稿的位置。改写时参照它们的句式和节奏，**只学句式，不借技术内容**。样本本身也可能有痕迹，不能整篇当标准。docx 样本先抽成纯文本再交给执行者读。

节奏可以用逗号与句号之比粗查，比值明显低于定稿样本说明句子偏碎。实测：第二篇首稿 1.64，用户审稿后 2.33，代理机构定稿样本 2.82。这只是提示，不作硬指标。

## 审计表格式

`去AI味审计.md` 一行一处命中：

| 编号 | 位置 | 区域 | 原句 | 类型 | 处理 | 改后 |
|---|---|---|---|---|---|---|

- 位置写到节和步骤（如「具体实施方式 S3」）；
- 处理取「已改」「只报」「保留」之一，「保留」要写理由；
- 权利要求的命中项一律「只报」，并给出建议写法；
- 一句有多种痕迹时按主要类型计一次；
- 给不出安全的建议写法时写明原因，不硬写。

**技术疑点单列。** 结论与表格不符、术语含义不明、证据缺失这类问题不算写作痕迹，写在表后「技术疑点」一节，只报不改，不计入命中数。

末尾写一段小结：每类命中多少处、改了多少处、有无不确定的句子。
