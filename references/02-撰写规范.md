# 阶段 2：撰写规范

这份文件的目标是**一次写成的稿子就达到代理机构两轮意见改完之后的水平**，而不是先写一版再等人挑。

下面每一条都标了出处。凡标「代理机构实际改过」的，是真实发生过的修订或批注，不是风格偏好。

---

## 1. 结构与命名

- 说明书五段式，顺序固定：**技术领域 → 背景技术 → 发明内容 → 附图说明 → 具体实施方式**。正文**不得有插图**，图一律放说明书附图。
- 第一行是发明名称，与请求书完全一致并居中，名称与正文之间空一行。
- **发明名称不超过 25 字**（代理机构批注：「最好压缩到 25 字以内」）。改名要同步五处：说明书首行、技术领域、发明内容、权利要求 1、摘要。漏一处就是三份文件不一致。
- 自造模块的命名**可以用英文术语**。但若名字借用了已有技术的名称（Transformer、Attention 这类），**必须在实施例里说清楚它到底是什么结构、堆叠多少层**，否则会被问「这个网络和 Transformer 有关系吗」（代理机构批注原话）。名字本身不必改，把实现讲清楚就行。
- 技术领域用**规范技术表述**，不用口号式或文艺化措辞。代理机构实际改过：「人工智能赋能大气科学」→「环境监测与时间序列预测技术」。

## 2. 公式与符号（代理机构最在意的一块）

### 2.1 符号说明必须紧跟公式

每个公式之后紧接一段「其中，A∈… 为…，B∈… 为…」，**严禁把多个公式的符号攒到一段统一解释**。

这一条的分量：代理机构第一轮 315 处修订里，绝大多数就是干这一件事——把一整段集中解释所有符号的长句**整段删掉**，拆成四小段分别插到对应公式的正下方。

写的时候就按这个形态写，不要指望事后再拆。

### 2.2 每个参数都要定义，一个不漏

公式里出现的每个符号，都要能在紧跟的「其中」段里找到定义。

分量：在另一份该机构经手的稿子上，「各个参数含义标注清楚」这条批注**出现了 5 次，全部挂在公式旁**。这是该机构最高频的意见。

交稿前做一次自查：把每个公式里的符号抽成集合，与「其中」段定义过的符号集合求差集，差集必须为空。

### 2.3 公式拆短

一式讲一件事，不写一个大而全的式子。拆短之后每一步怎么算才讲得清楚，也才好让从属权利要求逐条盯住。

### 2.4 维度必须自洽

逐式核对矩阵乘法的内维。真实教训：某稿写 `ΔX = W₂·GELU(W₁·O + b)`，但声明 `O∈R^{N×d}`、`W₁∈R^{d×d}`，内维 d 对 N 根本乘不通，被代理机构批注「行、列数是否有误」揪出来。

修法二选一：公式改成右乘（`O·W₁`），或把权重的维度声明转置。改完要回头核权利要求书里的同源公式是否同错。

### 2.5 记号要回指

损失函数、评价指标里用到的记号，必须与正文前面已定义的符号体系对得上，并写明「矩阵与元素」这类取值关系。代理机构批注过「和 X_t 的关系，显式说明下」。

**改记号体系之前先回查说明书开头的符号约定段。** 曾有一次误判为「一符两义」而提议改五个公式，实际上开头的约定段早已定义清楚，缺的只是一句取元素关系。只看局部段落容易把自洽的东西判成冲突。

## 3. 步骤与数据流

- 技术方案步骤化 S1–Sn，**只写算法、不写作用目的**。作用目的放具体实施方式。
- 步骤之间的数据流用固定句式：「**本步骤获得的 X 提供给步骤 SY**」。代理机构实际把「所得…用于步骤 S3」改成了这个句式；在另一份稿子上也在每步末尾补「用于提供给步骤 X」。
- 步骤描述**一句一件事**，避免长定语堆叠。代理机构第二轮把两个步骤的长句改短了。

## 4. 称谓与措辞

- 具体实施方式的主语用「**本实施例**」。「本发明」只在发明内容和技术方案里用。代理机构在另一份稿子上删掉了实施例里的「本发明」和「本发明提出的」。
- 表述要精确，避免同一个词指代两个层级的对象。代理机构实际改过：「第 t 个预测步的权重」→「第 t 个预测步的**步**权重」。
- 少用分号。正文散文里的「；」多改成「。」或「，」；权利要求里 S1–Sn 的步骤分隔保留「；」，那是专利标准写法。
- 序号用阿拉伯数字。代理机构第二轮把「表一/表二」的「一、二」改成了「1、2」。
- 表题、图题的编号后加顿号：「表一、XXX 的对比」。代理机构第一轮加的。
- 不写自夸和主观表述（「本发明提出的先进方法」「显著优越」这类），也不写绝对化措辞（「所有」「必然」「完全解决」）。

## 5. 术语一致性

- 全篇术语统一。改一个词就要全文批量改，包括附图内的文字。真实工作量参考：某一轮统一了 6 类术语共 104 处（其中两类分别 29 处和 42 处）。
- **权利要求书、说明书、摘要三处对同一技术方案的表述必须协调。** 摘要是说明书的浓缩，权利要求的每个特征都要在说明书里有支持。
- 改术语之后回头核附图：图里的字也要改，图题也要改。

## 6. 有益效果

- 说明书**必须有「有益效果」小节**。代理机构第一轮专门插入了这个标题并留了占位符，要求补写，批注是「结合本发明创新点说明下实施本发明能带来的好的技术效果」。
- 写法：**特征 → 机理 → 效果**，逐条对应创新点。不要只堆结论，要说清楚是哪个技术特征、通过什么机理、带来什么效果。
- 区分实测数据与理论预期，不把预期写成实测。
- 用**可度量的平实表述**。代理机构第二轮改过：「赋予精准长时预测的能力」→「提高了长时预测精度」。

## 7. 具体实施方式：每个步骤的七元素段落

**每个 S 步写成一段，按固定七个元素展开，缺一不可。**

| # | 元素 | 写什么 |
|---|---|---|
| 1 | 动作与输入 | 本步做什么操作、吃进什么数据 |
| 2 | 设计理由 | **为什么这么做**，不是怎么做。常见是工程约束、数据可得性、训练稳定性 |
| 3 | 机理说明 | 这样做在物理上或算法上意味着什么，解决了什么 |
| 4 | 公式引出句 | 固定句式，如「具体…的计算过程如下：」 |
| 5 | 公式 | 拆短，一式一事 |
| 6 | 符号说明 | 紧跟公式，逐个参数定义（见第 2 节） |
| 7 | 数据流向句 | 「本步骤获得的 X 提供给步骤 SY。」 |

示例（节选自真实稿件）：

> S2：取相邻两个历史时刻的数据 X_{t−1}、X_t。**仅选取两个时刻的原因为，真实场景中站点关闭和仪器故障使序列完整性难以保障；输入窗口越长，对完整性的要求越高，可切出的训练样本反而越少，不足以支撑训练。**将二者拼接后送入全连接层升维，再与位置编码拼接，使表示同时包含数值信息和空间位置信息。具体嵌入表示的计算过程如下：
>
> （公式）
>
> 其中，U_k∈…，c_k∈… 为可训练参数，TE_k∈… 为……的时间编码。
>
> 本步骤获得的嵌入表示提供给步骤 S3。

**元素 2 和 3 是「专利实施例」区别于「论文方法节」的关键。** 论文只讲怎么算，专利实施例还要讲为什么这么设计、这样设计解决了什么。缺了这两样，写出来就是论文的翻版，也撑不起有益效果那一节。

其余要求：

- 主语用「本实施例」。
- **每个超参在实施例里给出具体取值**。代理机构有两条批注专门要这个：「后面的实施例中，给出 k 的取值」「说明取值范围或典型值」。模块堆叠层数也要给。
- 说明书正文**可以用「例如」举例**（如「采用再分析数据（例如 ERA5）」）。禁「例如」这条只针对权利要求书。
- 要有完整数据流：读完实施方式，应该能照着实现一遍。

### 性能对比是可选的

有实验就写，没有就不写，**不得为了凑格式而杜撰数字**。

若写，结构是：指标定义 → 计算公式 → 符号说明 → 对比表 → 结论句（「由表可知，相比最优对比方法降低约 X%」）。指标公式同样适用第 2 节的符号规则。

硬性要求：

- 数字必须来自真实评估；
- 临时占位必须显著标注，且**递交前必须以真实数据替换或整段删除**，二选一；
- 不引用与说明书其他部分矛盾的实验设置（比如正文删掉了某个分支，就不能再引该分支的结果）。

这是诚实性红线，不是风格问题。

## 8. 附图说明

- **图题简短，不重复发明全名**，用「图X 中的…」互指。代理机构在另一份稿子上把「图2 为本发明一种基于…方法的主路径编码器」改成了「图2 为图1 系统中的主路径编码器结构示意图」；本案第二轮也把四条图题全部简化。
- 图号与正文引用、附图文件严格对应。
- **摘要附图的步骤框必须与发明内容的 S1–Sn 一一对应**：框数等于步数，每框文字是对应步骤的浓缩，顺序一致，不多不少。

  代理机构批注「步骤需要与发明内容一致」针对的就是这条。真实情况是：流程图还停留在早期的五步方案，正文已经改成七步，中间四步的技术核心在图里完全缺失。**改正文必同步改图，改图必回头核正文。**
- 附图标记（部件编号）清单要与图严格对应，有增删就重编号。

## 9. 权利要求硬规则

这些是 CNIPA 的要求，不是风格：

- 每一项权利要求**仅允许在结尾处使用一个句号**。
- 禁止「如图所示」「如说明书所述」这类引用式表述。
- 禁止「例如」「最好」「优选地可以」等含糊用语。真实案例：权利要求里的「（例如 ERA5 再分析数据）」被要求删除，因为「例如」属于审查指南不允许的含糊用语，容易招来不清楚的审查意见。
- 编号前不得冠以「权利要求」字样，用阿拉伯数字顺序编号。
- 权利要求中使用的科技术语应当与说明书一致。
- 独权前序统一写「一种……方法，包括以下步骤：」，与发明名称一致。代理机构第二轮补过这个「一种」。

## 10. 摘要与文末

- 摘要不超过 300 字。结构参照同领域已公开申请的惯例：「本发明属于 X 领域，公开了一种…，解决了…的技术问题。通过…。本发明…，有效提高…」。
- 摘要常见缺陷：缺「解决了…技术问题」这一句；机制细节过密，抽象层级低于摘要应有的水平。
- 摘要里不写广告语、法律结论、权利要求编号、未提供的实测值。
- 说明书末尾加兜底声明：「以上实施例仅用于说明本发明的技术方案，而非对其限制。本领域技术人员在阅读本说明书后，可在不脱离本发明构思的前提下，对其技术方案做出各种变形或修改，这些变形或修改均应涵盖在本发明的保护范围内。」代理机构第二轮新增的。

## 11. 格式基准

以下数值取自代理机构认可的一份实样（见 `范例索引.md`）：

| 项 | 值 |
|---|---|
| 正文 | 宋体 12 磅；西文 Times New Roman；公式 Cambria Math |
| 发明名称 | 宋体 14 磅，不加粗，居中 |
| 五段节标题 | 与正文完全同样式（12 磅不加粗、首行缩进两字符），不单独加大加粗 |
| 缩进 | 全部段落首行缩进两字符（悬挂缩进只用于模板自带的注意事项编号项） |
| 段前 | 60 缇 |
| 行距 | **固定值 24 磅**；例外：独立公式段与图片段用「最小值 24 磅」防裁剪，表格单元格单倍 |
| 权利要求编号 | 「1、」 |
| 步骤编号 | 「S1：」 |
| 图号 | 带图题，标在图正下方 |
| 摘要附图文件 | 不带图号标注 |
| 页面 | 用现行官方模板的 A4，不照抄旧样例的信纸尺寸 |

**这份基准会过期。** 参照样例可能是十几年前的旧表格，官方模板会改版。凡格式有疑问，以最新官方模板和代理机构的实际意见为准，并请用户在 Word 里直接查看实样确认（用 textutil 之类工具转换旧 .doc 会丢掉字体名和行距，据此判断会出错）。

**与 `04-Word打包.md` 的分工**：本节只说「稿件应该长什么样」，`04` 只说「怎么用脚本做出来」。数值只在这里出现一次，`04` 引用不重复。

## 12. md 骨架约定

草案写成 Markdown，由 `scripts/build_docx.py` 转成 Word。**从 `scripts/template.md` 复制着写，不要从零写**，因为脚本按固定标题切分，标题写错会切不出来。

约定：

- 五个二级标题一字不差：`## 一、发明名称`、`## 二、摘要`、`## 三、权利要求书`、`## 四、说明书`、`## 五、摘要图（说明）`；
- 说明书内部是五个三级标题，名称与顺序固定；
- 表格写成裸 HTML `<table>`，不用 Markdown 表格语法；
- `>` 引用块会被当作草稿批注**跳过**，不进 Word——可以放自己的备注，但别把正文写进去；
- 公式用 `$$`（独立成段）与 `$`（行内）。

## 13. 交稿前自查

不能自动化的部分，逐项人工核：

| 查什么 | 怎么查 |
|---|---|
| 公式符号是否都定义过 | 符号集合差集，必须为空 |
| 矩阵维度是否自洽 | 逐式核内维 |
| 名称是否 ≤25 字且五处一致 | 文本比对 |
| 摘要是否 ≤300 字 | 计数 |
| 权项是否每条只有结尾一个句号 | 标点计数 |
| 权项是否含「例如」「如图」 | 关键词扫描 |
| 有益效果是否结合了创新点 | 人工读 |
| 超参是否都给了取值 | 对照权利要求里的每个变量名 |
| 摘要附图步骤与 S1–Sn 是否一一对应 | 逐框核 |
| 术语是否全篇一致（含图内文字） | 拉一张术语表逐个 grep 全文与 drawio 源文件 |
| 实验数字是否为真实数据 | 问用户确认，占位必须已清除 |
