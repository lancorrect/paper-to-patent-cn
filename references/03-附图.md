# 阶段 3：附图

## 单一编辑源

**一个 drawio 文件装全部附图，页序即图号。** 不允许同一张图存在两份可编辑源。

早期把三张图拆成三个独立 drawio，很快就出现「改了哪一份」的混乱，后来合并成一个多页文件（合并时逐页核对 XML 元素数一致，确认无内容丢失）。往后所有修订都在合集的对应页签上做，PNG 从合集按页导出。

页签命名直接用图号语义（图1 的页叫整体架构、图4 的页叫摘要附图），不要用随手起的临时名。

## 合规硬点

- **摘要附图必须是说明书附图之一。** 做法是把流程图编进说明书附图（比如作为图4），请求书里指定它作摘要附图。摘要附图那个单独的 docx 文件里不带图号标注。
- **摘要附图的步骤框与发明内容的 S1–Sn 一一对应**：框数等于步数，每框文字是对应步骤的浓缩，顺序一致，不多不少。代理机构批注「步骤需要与发明内容一致」针对的就是这条。
- 附图用**黑色线条**，不着色、不加底纹。
- 图内文字用中文。

## 统一的样式标准

同一套图里所有元素的样式必须一致，否则看起来像拼凑的。实际定过的标准：

| 项 | 值 |
|---|---|
| 数据流箭头 | 正交折线、`#222222`、1.6 线宽、实心 block 箭头 |
| 装饰线（轮廓连线、放大指示虚线） | 不加箭头 |
| 双向箭头 | 保留双向，两端箭头形状统一 |
| 字号 | 全图统一，不混用多种字号 |
| 框尺寸 | 同类框统一尺寸，为最长的那条文字留够宽度 |
| 纵向间距 | 统一，不要 30/25.5/28 这种肉眼可见的不齐 |
| 水平位置 | 居中对齐到页面中轴 |
| 填充 | 显式白底黑框，不依赖 draw.io 默认样式 |
| 文字标签 | 剥成纯文本，样式全走 mxCell style，不要留 Word 粘贴带进来的 `line-height`、`text-align:start` 残留 |

流程图页如果不含 LaTeX，把页属性 `math` 设为 0，免得希腊字母被误渲染。

## 人机分工

- **Claude 能直接改 drawio 的 XML**（它是 XML，可程序化编辑）。
- **Claude 不能调用 draw.io 导出 PNG。导出这一步必须由用户操作。** 不要承诺能自动导出。

## 两个必查

1. **改 drawio 前先 `pgrep -fl -i drawio` 确认没开着。** draw.io 和 Word 一样，读进内存后不再盯磁盘，开着时脚本写入零报错，用户一保存就把改动静默覆盖。
2. **图文一致性要核图内的每个词，不能凭图号推断。** 曾经断定「四张图都含待改术语，必须一起重画」，逐图核对文字后发现其中一张用的是另一个词，根本不受影响，白白把它压在阻塞队列里。结论下在图号层面就会失真。

## 改术语时的连带范围

改一个术语，要一起改的地方：正文（说明书、权利要求书、摘要）、附图内的文字、**附图说明里的图题**。图题最容易漏，因为它在正文里，看起来不像「图的事」。

## 把新图换进 Word

Word 内嵌图片不会因为 PNG 文件更新而自动更新。三种做法：

| 做法 | 有没有修订痕迹 | 何时用 |
|---|---|---|
| 用户在 Word 里「更改图片」 | 无 | 成稿阶段，没有修订要求时 |
| 脚本替换 `word/media/imageN.png` 字节 | 无 | 同上，且 Word 必须关着 |
| **修订模式下删旧图 + 插新图** | **有**（旧图包在 `w:del`、新图包在 `w:ins`） | 给代理机构回稿时 |

第三种是实测可行的：Word 会照常留痕，作者名同样按当前登录账户判定。所以在带修订要求的文件里换图，不必额外发邮件说明「换过图」，痕迹自己看得见。
